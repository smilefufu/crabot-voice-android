# 短句声纹识别实施计划

依据：用户确认的同日[修订稿](../specs/2026-10-14-short-utterance-speaker-identification-design.md)，正式 protocol-voice v0.5.0。只改安卓端，不改共同网络字段、存储或权限。

1. 独立公开登记与短句测试文件准备 → 核对官方源摘要，原始WAV及派生片段只放忽略的模型缓存；指定真机测试在旧逻辑复现跳过比对。只用内存测试样本，不读写真实声纹/配对或开启麦克风。
2. 日常提取取消固定秒数限制，保留登记24000 samples要求 → 现成JNI的IsReady负责是否有可计算特征；覆盖短句、未就绪、无效向量/匹配结果、单候选低分、相近候选及SDK异常。记录只包含允许的VoiceSegment字段。
3. 本地诊断与首页未确认原因 → reason与输入时长/是否比对/分数独立于wire，不写入声纹存储；逐人时间轴保持，下一轮清旧诊断，未确认不猜测名字或音频原因。
4. JVM及指定隔离仪器回归、完整APK构建、简化检查及diff review → 仅运行已审查无清数据/采音行为的测试类，真实密文前后逐字节一致。
5. 保留数据覆盖升级并打开App → 原配对、有效样本、关麦和后台目录不变；用户现场说自然短句，核对是否实际比对、匹配结果、后台身份及播放回执。通过相关验收后Android直接main；尚无多人现场条件的部分继续标待验收。

复用语义：NativeModels.embedding只为当前匿名簇提取特征，已有IsReady/空向量行为不等于身份确认；NativeModels.matches只比较当前有效候选，不借它授予好友或群权限。模型接口的窄测试替身只验证输入/时间轴/匹配语义，真实文件测试另验JNI模型路径；不能把替身的高分当作真人声纹证据。
