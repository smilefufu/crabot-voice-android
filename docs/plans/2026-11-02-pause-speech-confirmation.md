# 暂停期间的人声确认与控制器隔离接入

依据已确认自然轮次两端spec及protocol-voice §5、§8；不改协议/提示词/身份/业务任务流程，不部署、连接ADB或采集真人声音。先补完源码与自动验证，组件门槛不等于声学验收。

| 步骤 | 验证方式 |
|---|---|
| 复现暂停后失去判断 | 固定接受写入与硬件时间戳，暂停在队列中间；继续输入时AEC必须拿到真实已播历史及暂停后的静音，而不是null或未播的后半段。先在旧代码取得失败。 |
| 对齐真实参考 | PCM只来自成功write；按硬件样本时钟与真实游标保留有界参考历史。暂停/饥饿形成静音区间，恢复沿原游标重新取得硬件锚点，不用回调时间伪造采样。无锚点/历史缺口明确不可判断。 |
| 本地两级确认 | 使用所选WebRTC组件自带默认VAD提出候选，原Silero及原配置确认；不是新增端点模型，不改声纹或原VAD阈值。确认前不产生业务turn/上传；纯噪声候选恢复同一播放器，持续不确定沿原1秒故障边界。 |
| 控制器隔离接线 | 以内部音频依赖接入实际VoiceController，固定旧turn/playback/epoch。确认后只取消旧输出消费，保留300ms前导，新轮仍走原身份/完整准入；正常等待/播放的本地音频不上传。用可控端点依赖验证，不把未过关EOT模型启用到默认wire9。 |
| 回归与交付 | 固定公开回声/双讲和暂停重放；30轮正/反候选与旧消息/关麦竞态；全部JVM、JNI/Android构建、完整diff审查。无阈值或EOT超时试调；失败保留并收窄结论。 |

语义复用：原stop会撤销本轮采音并清空所有缓冲，不能用于候选暂停或直接用于保留连续输入的确认切轮。候选只操作实际旧Playback；确认路径显式结束旧输出与旧计算，再建立新turn，不取消已接纳Worker。原身份处理仍取得原采音，AEC输出仅供本地检测；旧向量兼容与软件/系统AEC切换仍须真机核验，默认路径不切换。通知不得创建免唤醒许可。测试依赖不能作为产品能力自报或资格证明；中文EOT未通过，实际模型/硬件未验收前不发布自动模式。
