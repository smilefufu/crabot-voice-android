# 持续待机的独立实现与验证

依据：已确认的[自然轮次设计](../specs/2026-10-27-natural-voice-turn-taking-design.md)及正式[protocol-voice §5、§8](https://github.com/smilefufu/crabot-docs/blob/main/protocols/protocol-voice.md)。这是已确认设计中的待机恢复部分，不修改端点模型、800ms输入边界、自然打断、协议版本、身份或业务执行流程；完整wire10仍待后续组件/联合验收，不部署部分实现。

| 步骤 | 验证方式 |
|---|---|
| 复现异常关麦 | 电脑Robolectric运行真实VoiceController与Android队列，假采音/假本地模型/假传输；固定无回复、服务端取消、预留超时、设备播放失败与旧检测回调，先取得原实现失败。 |
| 最小恢复修复 | 普通交互结束集中核对原前台、连接epoch、目录/模型及原许可；可恢复时回KWS，不创建8秒免唤醒、不重传/重播/重跑任务；本地设备/检测及未知错误撤销许可。 |
| 保留结果与隔离旧对象 | 已结束turn的response_end、旧播放取消/回执、旧采音检测异常不能清除新输入。结果提示独立保留，正常状态文案不覆盖上一轮失败。 |
| 自动生命周期 | 至少30轮，分别验证成功接话、无回复/ASR拒绝/TTS取消、通知恢复、静音、后台/失联/目录失效；断连后回前台不自动开麦。 |
| 构建和审查 | 新旧JVM测试、产品及instrumentation编译、依赖摘要增量检查和本次完整diff review；不连接ADB或安装手机。 |

语义复用：原`stop`清理本轮音频、取消原ID及候选登记，不是通用的“恢复待机”入口；新恢复方法只用于普通语音交互，先沿原`stop`结束本轮，再重新核对原许可。guided管理失败仍按既有边界关麦，不借普通服务失败重新授予采样。`standby`只开本地KWS，不能创建业务turn、上传环境音或恢复旧输出。

组件准确率与Controller自动验证分开记录；主机控制器通过不等于原手机收音、模型准确率、AEC或自然对话通过。相关模型仍未过门槛，不因此联合升级、不要求用户反复测试。
