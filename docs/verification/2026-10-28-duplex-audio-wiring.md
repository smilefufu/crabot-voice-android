# 音频底座接线与自动验证

2026-10-28。依据已确认自然轮次spec，完成隔离音频会话的真实设备适配器、APM JNI、采音时钟及播放器候选暂停/恢复。**没有把现有VoiceController的wire9链路切换为自然插话，也没有宣称中文判停/真机AEC通过。** 本机部署、手机、ADB、原业务音频/身份输入及提示词未改。

## 本轮实际实现

- `Microphone.startTimed`返回每次读取的样本位置和AudioRecord的MONOTONIC硬件时间戳，重新启动重新计数；每次录音使用独立停止标记，旧采音线程不能因重启重新运行。
- `Playback`仅把AudioTrack实际接受的PCM范围交给参考，零写不产生参考，部分写不丢不重；硬件timestamp用于声学时间映射，实际送达仍用playbackHead，写入/提交给HAL不冒充已听到。
- `DuplexAudioSession`将真实AudioRecord/AudioTrack适配器与24k render、16k capture的10ms APM JNI接起来。由原生命周期所有者显式打开/关闭，构造不采音，不包含网络或业务turn；软件AEC路径核实关闭系统AEC，不叠加两套。
- 同一播放器的候选pause/play保持原队列/游标/播放ID；确认才终结为interrupted。最多1秒候选及1秒总在途预算分别检查，不重置原5秒游标看门狗。过期、路由变化和恢复设备失败终止旧播放器，旧候选不能操作替换对象。
- 源码、依赖归档及解压内容逐文件校验；Meson thin archive转为可移植的普通静态库，沿现有NDK编入`libcrabot_voice.so`。许可随APK分发，无第二份C++/ONNX运行库。

## 尚未完成的边界

1. 新音频会话尚未被现有wire9 Controller选用，自动候选检测/确认、业务cancel与新turn衔接仍待资格通过后的整合；此次完成的是设备/APM/播放器组件和其真实I/O接法。
2. 暂停期间声学时间映射会失效，本实现把相应块标为不可供自动判断，恢复后重新等硬件时钟。**暂停期间如何持续可靠判定近端讲话仍未接通**，不能用本轮pause/play通过来冒充完整自然插话通过；不能让该候选无限停住，原一秒故障保护仍生效。
3. Android HAL时间戳可用性、采音/播放漂移、实际AEC/双讲、让声P95、功耗和原声纹兼容尚未进行设备验证。公开软件混音或host JNI相同不能证明这些效果。
4. 中文端点模型仍未通过原固定门槛；保留原失败、标签及阈值，不通过延长超时替代判停。wire10联合实现/升级、真正自然续聊及真人验收均未完成。

本轮无spec/协议/提示词变更，无数据迁移，也没有自动开启任何麦克风。后续若需改变上述已确认边界，先说明并确认；本轮不因组件完成安排用户重测。
