# 持续待机恢复：控制器验证

日期：2026-10-28。依据已确认的[自然轮次设计](../specs/2026-10-27-natural-voice-turn-taking-design.md)与[实施计划](../plans/2026-10-28-standby-lifecycle-implementation.md)。这是待机部分的源码修复，未联合发布；产品版本仍保留 0.8.2/code19/wire9，不能视为完整 wire10 实现。

## 修复结果

| 已定位路径 | 原行为 | 本次行为 |
|---|---|---|
| 空回复结束、服务端取消播报、播放预留到期 | 停在 CLOSED，待机意图与实际采音不一致 | 结束旧交互；原前台、连接、许可、目录和本地模型仍有效时回本地 KWS，不新开免唤醒窗口。 |
| ASR 拒绝、回答等待释放 | 结果容易被后续状态覆盖；清理入口不一致 | 统一结束旧交互并保留原因；不重复提交或取消已接纳的业务任务。 |
| 本机播放、检测或输入处理失败 | 部分路径只关闭当前采音，仍显示待机许可存在 | 关闭采音并撤销待机，明确提示用户检查后再开启。服务端普通取消与本地故障分别处理。 |
| 旧采音检测回调 | 可向新一轮模型送入旧帧，或迟到异常关闭新采音 | feed 前核验原 capture generation，排队异常执行时再次核验。 |
| 结果提示 | 普通连接状态可能覆盖上一轮失败 | 单独保存上一轮结果，开始新输入时清除；新故障仍可显示。 |

不改登记重试、身份、阈值、提示词、业务流程、协议字段、判停模型或 800ms 收尾。guided 管理失败仍保持关麦。通知只恢复原状态与原接话截止时间，不延长窗口。静音、后台、断连、目录无效、本地故障或未知错误均不能借恢复入口重新开麦。

## 复现与回归

先在原控制器 `3d6488a` 上加行为不变的模型测试边界，执行首批 8 项用例：5 项失败、3 项通过。失败分别为：空回复、服务端播报取消、播放预留到期、本机播放失败后的许可、旧检测回调影响新输入。原控制器 SHA 和逐项结果保留在[脱敏证据](2026-10-28-standby-recovery.json)。

修复后扩展至 23 项控制器用例，加原有 30 项 JVM 用例，共 **53 项全部通过，0 跳过**。覆盖：

- 30 轮实际调用控制器 completed 回执→接话窗口→KWS，30 轮空回复／ASR 拒绝／服务端取消→KWS。输出回执与输入事件由固定替身提供，不是手机播放。
- 空回复或普通服务失败不创建免唤醒、不上传待机音频；手动单轮结束不授予持续待机。
- 旧 turn、播放 ID、真实预留计时器、旧帧及已排队检测错误不关闭新录音。
- 接话第 7 秒已开始的输入不被原第 8 秒定时器截断；通知不延长原截止时间。
- 静音、后台、断连、新连接、目录失效、本地模型缺失、检测／处理／播放错误及管理失败均核对实际采音和许可；恢复目录或连接不能自动开麦。
- 旧消息、目录确认不覆盖上一轮失败；本地处理失败不提交 turn_end。

这些测试执行真实 `VoiceController` 和 Android 主队列（Robolectric 4.17、SDK29、PAUSED Looper），只替换采音、模型返回值和 WebSocket；模型初始化在调度前取消，不加载 JNI，不访问真实配对、声纹、录音或设备。没有测 ASR、TTS、云端模型、真实麦克风或扬声器。测试不把全部错误伪造成可恢复，也不依赖模型偶然输出。

## 构建、依赖与审查

已有 Java17/Android35 工具链与缓存中执行：

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest --offline --no-daemon --console=plain
```

最终运行 11 秒，三项目标成功；instrumentation 只编译，未上手机执行。首次准备 Robolectric 需要测试依赖和 Android 测试 runtime 下载，不能把已有缓存的离线构建当作全新环境无需下载。

仅增加测试依赖；Gradle 验证配置和原 347 个组件的全部摘要不变，新增 37 个组件固定 SHA-256。APK 和源码摘要见证据；APK 未安装，不作为正式版本发布。

最终审查覆盖全部本次产品、测试、依赖和记录 diff。结果处理集中在一个普通交互收尾入口，保留登记例外与既有通知恢复；未发现需要额外抽象或行为不变重构的部分，未另加简化步骤。新增故障收口：本地恢复启动失败撤销许可，迟到回调按原 generation 丢弃并清零音频；不重传、重播或重跑业务。
