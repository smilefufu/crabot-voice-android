# 暂停后持续判断与实际控制器接线

2026-11-02。按已确认自然轮次设计实施，不改变spec、正式协议、提示词、声纹、模型阈值或超时。**本轮完成软件链路，未启用默认手机链路，也不记作自然对话验收通过。** 没有访问ADB、安装APK、采音/播音、付费API或改本机部署。

## 修正的问题

旧实现暂停后把播放时钟标为不可用，后续采音无法持续送入APM，因而不能完成“先暂停，再判断是否真的有人插话”。先在旧代码取得回归失败，再修复。

接受写入的PCM与实际播出的时间现在分开记录：暂停在真实消费游标处关闭一段播放，未播尾部保留；暂停后的物理时间使用静音参考，历史回声仍由APM连续处理。恢复同一播放器，从原游标重新取得硬件时间戳，直接使用此前已接受的未播PCM。分段饥饿也形成静音区间。时间戳尚未取得时保留原采音，最多一秒，不跳块或猜测参考。

检测使用既有WebRTC组件默认VAD提出候选、原Silero及原配置确认，独立JNI所有者避免声纹计算阻塞实时检测。APM清理结果只供本地检测；身份/分段和上传继续取得未经替换的原采音。

实际`VoiceController`已接入这一内部音频依赖：候选撤销恢复原播放器；确认后结束旧输出消费，保留300ms前导并建立新turn，重新走原身份/完整消息准入。只取消本地旧计算及语音消费，不取消已接纳Worker。等待/播放期间本地采音不上传；旧turn/playback/endpoint结果不能终结新输入，未知音频及全局错误仍拒绝。通知不授予监听许可。

## 未完成与发布边界

1. 中文EOT仍未通过资格门槛。`TurnEndpoint`仅是显式非阻塞依赖，本轮测试使用受控结果；没有默认模型、定时兜底或能力自报选路。原失败样本、标签、阈值及超时保持。
2. 默认`VoiceController(context, changed)`仍使用wire9旧链路；生产入口未选择新依赖，无版本/协议升级。自然输入依赖存在时不再用800ms静音提交，但此源码路径尚不发布。原15秒输入容量保留，超出则明确拒绝而非截断提交。
3. 实际手机的时间戳可用性/漂移、扬声器回声、让声与短词确认、功耗、原登记声纹兼容仍未验收；不能拿软件混音和受控Controller测试代替。
4. 后端wire10联合检查/升级、真人连续对话和首声验收仍待前置门槛通过。本轮无需用户重复测试。
