# 设备所有者首次激活与配对

日期：2026-10-15
状态：待用户确认；仅设计稿，未修改 APK 或真实设备数据。

配套[后端自动认主设计](https://github.com/smilefufu/crabot-docs/blob/main/superpowers/specs/2026-10-15-voice-device-owner-activation-design.md)。正式跨端类型、状态和权限规则只以 [protocol-voice](https://github.com/smilefufu/crabot-docs/blob/main/protocols/protocol-voice.md) 为准，本仓不复制协议 schema。

## 1. 目标与最小流程

新设备首次打开按“登记本人 → 连接 Crabot → 完成”引导，设备所有者声纹必须先于首次配对完成。既有已配对设备升级不强制重新激活；不重复要求录制 FuFu，也不导入实验 App 数据。

用户只需填写所有者名字、按提示完成三段不同内容的采样，再扫描后台二维码并完成既有核对。配对步骤明确显示“设备所有者将关联为 Crabot 的 Master”，不另设好友选择或绑定确认。ASR/TTS 服务仍在 Admin 配置，不在手机增加模型服务表单。

非目标：所有权转让、多所有者、跨设备声纹复制、离线编辑整个渠道名册、私聊切换、锁屏/后台采音以及新声纹模型。

## 2. 所有者档案与采样

所有者是独立、稳定的本地人物档案，当前声纹是可替换样本；不能将数组第一个元素、显示名或“最后录入的人”作为所有者。首次登记成功才创建档案；后续所有者重录保持其引用。删除样本不删除或转移所有者。

首次登记沿现有三段现场采样预算：每段 3–5 秒、有效人声不少于现有登记下限、单人且无重叠，特征维度/有限值/范数有效。三段须通过相互一致性检查后才合成有效档案；具体共同校验与阈值见[语音引导登记稿](2026-10-15-voice-guided-contact-management-design.md)，日常短句识别不增加时长门槛。初始登记允许页面操作，不依赖尚未配置的云 ASR/TTS；页面给出足够长的不同读句和录制进度，失败说明重录哪一段。

正常引导一次开始后按段提示、自动停录，不要求每段手动开始/结束；保留显式取消。系统麦克风权限按实际采音时申请，权限拒绝有恢复入口。没有网络、没有 Crabot 地址或 ASR/TTS 服务不妨碍本地登记；本地声纹模型未准备好时显示真实状态，不能空建档案。

原始音频只做有界内存处理，完成、失败、退出后释放；向量、模型信息和本地稳定档案引用使用现有 Keystore 加密并原子保存。配对前不产生正式渠道联系人/registration ID，不显示“已是 Master”。

## 3. 配对、映射与成功反馈

本地完成后进入扫码配对。手机报告的只是所有者描述与就绪事实，不发送向量、录音、friend_id、Master 或权限配置。描述与本次核对绑定，扫码后修改所有者须取消本次配对重新核对。

后台分配正式联系人和登记 ID 后，手机先原子保存所有者到后台 ID 的映射及待确认回执，再报告已保存。映射不重算或上传向量，不要求用户第二次采样；模型不兼容显示需重录，不能静默更改模型标签。后端完成联系人/active 登记和 Master identity 绑定后，手机才能显示“已连接，所有者已关联”，并清理本次待确认状态。

只收到 paired/credential 时显示“正在完成所有者关联”，不能提前宣称激活成功。连接成功、所有者关联和语音服务可用分别反馈；服务配置未完成时显示“请完成后台语音服务配置”，不退回重新录入或清除已成功身份。

首次完成后仍关麦，首页给出一次“开启语音待机”；不会因为配对成功自动开始监听。后续唤醒、8 秒接话、播放关麦及静音规则保持。

## 4. 生命周期与恢复

| 情况 | 手机行为 |
|---|---|
| 本地采样失败/取消 | 不建立完成档案；已确认的旧所有者样本不受影响。 |
| 二维码过期/连不上 | 保留本地所有者，返回重扫，不要求重新录三段。 |
| credential/映射保存失败 | 不发送保存成功回执、不显示完成；保留旧密文和原激活操作供恢复。 |
| 后台成功但响应丢失 | 查询原操作并取得同一 ID/完成事实，不新建第二人或再次认主。 |
| 退后台、锁屏、来电、断连、静音 | 立即停止采音与播放；保存已完成阶段，返回前台仍关麦，不自动补录或补播。 |
| 所有者删声纹/重录 | 所有者及联系人引用不变；删样本后不可识别，重录成功前保留原有效样本。 |
| 已有渠道身份冲突 | 显示后台返回的恢复提示，不按名字、列表顺序或新声纹覆盖原所有者/Master。 |

首次本地采样是前台有限过程，连续采样总预算 60 秒；无操作超时停止采音，重新开始须明确操作。网络配对仍用原 60 秒二维码，不拿其截止时间覆盖本地档案寿命。后台激活操作的未完成状态由原 ID 查询恢复，手机不能自行宣布其过期后换新 ID 重做副作用。

## 5. 兼容与旧设备

现有加密格式强制 pairing，需增加可保存“仅有所有者、尚未配对”的新存储版本；新 wire 与后端激活/语音管理稿统一拟为 6。具体字段在正式协议确认后逐项对齐，不先在设计稿维护第二套类型。

迁移先备份且原子替换，失败保留原密文、Keystore 和明确原因，不清数据。已配对老设备保留 credential、向量、联系人 ID 和历史：收到后台已验证的既有 Master 联系人关联，且本机确有兼容样本时，建立指向该人物的所有者引用；不能把现存第一条声纹当所有者。缺少依据时保留现状并提示恢复，不偷偷再次认主。

新手机连接已有渠道不借首次激活流程转让所有权。原手机重连或同渠道重新扫码，不重做自动 Master 绑定，不自动变更群权限、好友名字或授权。

## 6. 步骤与验收

| 步骤 | 验证方式 |
|---|---|
| 引导与本地登记 | 无后端/断网/权限拒绝/模型未就绪分别覆盖；成功前无完成档案，三段质量、一致性、取消和超时有明确结果。 |
| 配对与映射 | 同档案同配对的报告可恢复、描述变更使核对失效；收到 ID 后先落盘后回执，失败不假成功。 |
| 故障与升级 | 进程退出、回执丢失、每个写盘阶段失败、旧版迁移失败；保留真实样本与 ID，不卸载或清用户数据。 |
| UI与实际状态 | 联系人/好友完成前显示同步中；模型服务故障和认主结果分别显示；配对完成后麦克风保持关闭。 |
| 真机 | 隔离首次实例完整登记和配对，后台联系人/Master 关系可查，首次正常唤醒识别本人；另测旧 FuFu 数据保留升级。 |

确认后先更新后端正式协议，再编写安卓实施计划；定向验证和本次 diff review 后直接提交 main。当前只写 spec，不安装 APK、不重启服务、不操作现有声纹。
