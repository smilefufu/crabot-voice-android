# Android 任务反馈与播放时机修订

日期：2026-10-17。用户已确认业务流程并要求更新spec，书面修订稿待核对。本轮仅文档，未改产品代码、APK、手机数据或现场服务。

## 1. 目标与归属

Crabot 原有主控/Worker 已负责接单、执行、验收和完成回报；Android 不新增任务执行、通知任务、任务调度或语音模型。手机只报告自己是否适合发声，接收后台按原目标交付的声音和文字，记录真实播放事实。原提问结束或经过60秒不能使任务的完成回报丢失。

后端业务与交付语义见[任务反馈与播放时机修订](https://github.com/smilefufu/crabot-docs/blob/main/superpowers/specs/2026-10-17-voice-async-response-lifecycle-design.md)。共同字段、状态消息、鉴权与版本唯一在[protocol-voice](https://github.com/smilefufu/crabot-docs/blob/main/protocols/protocol-voice.md)维护；本仓不复制wire定义。两端须按正式协议协调升级，不用旧turn伪装新的任务结果。

本稿替代增量播放/日常交互旧稿中“原回答结束后不能再收到任务回报”的限制；原输入音频、失效连接和已经播出的声音仍不能自动重放。配对、声纹、唤醒、AEC和全语音管理的采样许可不变。

## 2. 日常状态与发声

- 前台、已连接、允许发声且空闲时，可以接收正常任务完成回报，不要求用户重新唤醒、补问或保持原录音轮次。长任务等待期间恢复现有日常状态，不一直显示为本次回答还没结束。
- 当前正在录音、处理一轮提问或播放回答时，报告忙碌；后台结果在当前轮结束的间隙接上，不中断人声或混播。不通过持续录音/上传环境声音判断别人是否在聊天。
- “静音”保持现有语义：关闭麦克风、停止发声。PROCESSING/WAITING/PLAYING期间的临时关麦不是用户静音；只有后者禁止主动结果播放。本稿不新增分开的采音/音箱配置开关。
- 静音、断连、退后台、锁屏、来电、音频焦点或路由异常时，立即释放录放音，清空失效音频帧；尚未交付的结果仍由后台按原结果保留。登记采样或其读句占用期间不插入普通任务声音。
- 回前台或重连保持静音，不自动开麦或发声；在现有入口明确恢复语音后，先同步真实回执和待通知情况，再在合适间隙接上结果。只恢复网络不代表用户愿意开始听。
- 主动任务结果本身不额外开麦、不启动本地唤醒、不新建8秒接话窗口；现有主动对话的回答保留原接话规则。播放结束只恢复此次播放前仍被允许的状态，不延长已经到期的接话窗口。

后台只能发送已经按原会话和任务核验的结果，手机不能凭声纹/最近说话人切换原任务的权限或目标。确需私发的结果不进入共享音箱；手机不展示其数量或摘要。

## 3. 有温度的反馈和最小界面变化

Crabot 在合适间隙自然接回用户交办的事情，而不是向用户报告一个播放系统的状态。例如：“对了，刚才那份资料我找到了……”；只有一件短结果直接说明，多项积压先给核心结论；已有可接话的交谈中，确有选择需要时再自然问“你想先聊哪件？”，不在关麦状态抛出要求立刻回答的问题。

不要求每项完成后确认是否播放，不使用“是否播报结果”“N条待播报消息”等功能口吻，不按固定模板反复招呼、点名或撒娇。仅依据真实结果与当前对话组织文字，不假定用户一直在场或已经听见。

正文仍由Crabot主控生成，Android不另接LLM、不本地编造摘要或固定业务结果。手机只展示后台确认的可公开待通知情况、最近实际接收的回答及真实播放状态；静音时以安静的视觉标记保留提醒，不新增弹窗确认链路、后台系统通知或自动跳转。

恢复后不从手机缓存连读旧音频；后台按原会话允许交付的结果生成一次简短衔接。没有有效配对或无法核验来源时不接纳新播放，不能为了显得自然而绕过失败状态。

## 4. 播放、停止与恢复事实

每次新的播放仍绑定当前有效连接及独立播放身份，接纳时核验前台、音频可用状态和忙闲情况；不能通过持久保留旧currentTurn或恢复旧PCM来实现后台结果。状态在接纳和播放之间改变时，立即拒绝或停止，并如实报告。

保留现有逐句PCM、有限缓冲、AudioTrack实际播放游标与completed条件。收到文字、合成完成、收到全部音频或写入AudioTrack不等于播放完成。队列接纳不冒充成功，不以本地猜测替后台清除任务回报责任。

用户停止当前声音后，不在稍后自动从头重播同一段；停止声音不取消业务任务。新输入只结束旧的实时播放尝试，不删除旧任务结果。已播部分或播放回执不明时保持未完整播放/未知事实，不猜逐字截止点；用户之后询问时由主控沿正常新请求说明已有结果。

重连先使用原身份核对后端和端侧已有回执：已经completed的不重复；从未开始的可由后台在允许状态安排；部分或未知不自动重播整段。若应用重启前已播放但回执未送达，核对依赖必要的播放回执元数据，不保存录音、生成PCM或重建采音许可。

配对、TLS pin、Keystore、声纹和联系人保留。只为新能力增加必要的端侧状态/回执兼容，不扫描旧播放历史猜测未通知结果；持久数据变更按正式协议与最小迁移方案核验，失败不伪造已同步。

## 5. 实施与验收

| 步骤 | 验证方式 |
|---|---|
| 对齐跨端契约 | 实施前读取更新后的正式protocol-voice，核对播放接纳、busy/静音/生命周期、回执恢复及版本拒绝；不在本稿另冻字段。 |
| 长任务和继续聊天 | 原问答结束、超过60秒、用户又问其他问题后，仍可接收原任务结果；不持有原录音轮次、无额外任务/Worker，未开麦时不被结果打开。 |
| 发声时机 | 空闲直接说；录音/当前回答/管理采样不被插入；当前轮结束有机会说出待通知结果，多个结果不双路混播。 |
| 静音与生命周期 | 静音/后台/锁屏/断连/焦点变化立即停录放音；网络恢复仍静音，明确恢复语音后只做自然衔接，不连读积压旧音频。 |
| 事实与去重 | 已播完不重复、未开始可正常安排、部分/未知不自动重播、停止后不重排；新结果不冒用旧turn/epoch，迟到帧不能影响新播放。 |
| 表达与界面 | 正常完成直接给有用结论，多项积压自然衔接，不机械询问播放许可；没有假任务、假好友、假ASR气泡或推测用户感受。 |
| 真机 | 覆盖安装保留原数据，用户协助验证长任务、插话、静音、掉线恢复及后续接话；手机真实听感和播放回执分别记录，不用模拟通过代替。 |

非目标：手机执行后台业务、独立通知Agent、后台/锁屏播放、系统推送、持续环境监听、AEC/自然抢话、多终端路由或新的全局人格。未核对书面稿、同步正式协议及确认必要模型文字前，不实施产品代码。
