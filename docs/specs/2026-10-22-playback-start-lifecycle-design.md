# 播放启动时序配套修订

日期：2026-10-22。状态：**用户已于2026-10-24确认；后端按正式协议实施，安卓产品代码不变**。配套[后端最小修订](https://github.com/smilefufu/crabot-docs/blob/main/superpowers/specs/2026-10-22-voice-playback-start-lifecycle-design.md)，正式跨端定义仍唯一见protocol-voice。

## 问题与选择

已在原0.8.0产品上用隔离缓存、假socket及合法内存前置状态复现两条旧序列：等待3.3秒后播放预留已被清理；收到空尝试的playback_cancel后原turn也清空。它们是跨端播放时序的缺陷证据，不是声音识别或历史所有失败的根因，也不是新方案必须继续发送的序列。前置数据无效的第一版实验已剔除，见[复现记录](../research/2026-10-22-playback-start-lifecycle/README.md)。

推荐后端仅在有非空白正文后申请播放，并在手机ready/必要记录完成后立即发送原playback_start，随后再发送已验证的音频；不把手机3秒预留拉长为另一个合成超时。原0.8.0隔离兼容验证已通过：立即start后等待3.4秒再送7200个静音样本，实际started/completed正确、未提前报发声且麦克风关闭。该证据支持无需修改安卓产品或重新配对。若实际互操作证明需要客户端变更，先报告最小偏差再实施。

## 保持的事实与边界

- playback_start只是输出会话开始，不能计作首声或送达。started仍依据真实播放游标，completed仍须完整消费；当前AudioTrack及回执层不替主控结算任务。
- 首音频/合成/消费/收尾继续按正式协议预算；仍关麦播放，静音/后台/断连停止，不因打开输出会话而启动8秒接话。
- 空头/空块的原模型重试不应再制造终端播放及取消。正文外发后的未知/失败仍不自动重播，用户明确停止照原规则处理。
- 不改wire字段/握手/存储、模型、身份、权限、联系人或配对；不新增SSML、任务流程、私聊或自然抢话。

## 验收顺序

确认后先同步正式协议的启动阶段解释，再按后端方案实现。用已配对手机之外的隔离状态验证：立即start后延迟3.4秒到PCM仍能正常实际started/completed；开始会话本身不报告发声；拒绝ready、不完整WAV、断连和按钮停止均保持失败事实。测试不发送response_end触发真实接话、不访问真人登记，不跑完整connectedAndroidTest。

原空序列诊断不入常规测试目录；新回归须使用修订后的合法生产序列，再覆盖原普通回复、notification、长答与真实回执。只有实际证据需要时才邀请用户体验，不再重复声纹朗读。
