# Android 增量语音播放修订

日期：2026-10-13
状态：方案方向已获用户同意；本书面修订待确认，确认前不修改产品代码。

## 1. 目标与归属

配合 Crabot 从 `<voice_reply>` 中提取文字、逐句 TTS，在整段模型回答结束前播放第一句。手机只接收音频、展示纯文本并报告播放事实，不解析模型 tag，不调用 LLM 或 TTS 服务。

[后端配套 spec](https://github.com/smilefufu/crabot-docs/blob/main/superpowers/specs/2026-10-13-voice-tag-streaming-replies-design.md)定义 tag、专用系统提示词、出站权限与重试；[protocol-voice.md](https://github.com/smilefufu/crabot-docs/blob/main/protocols/protocol-voice.md)在确认后更新为唯一跨端契约。本仓不维护第二份 wire 类型定义。

本次只改播放器和必要交互状态。声纹、联系人、配对页面、唤醒词、采音/VAD、ASR、权限和音频模型配置沿用现有设计；创建/登记修订独立待确认。

## 2. 用户体验与播放

- 用户仍点现有“开始说话”，没有新增日常按钮。播放中保持麦克风关闭，已有按钮可立即停止播放并重新开始一轮。
- 同一标签块的各句共用一个播放器/播放 ID，连续收到并播放音频；句子之间不进入接话窗口，也不继承已识别的 speaker。
- 开播时不要求知道最终长度，显示首句；结束消息更新完整纯文本并给出最终样本数。完整收到不等于完整播放。
- 一个标签块播放完成后，等待当前 Manager 的后续回答并保持关麦。例如短确认、工具执行、结果播报可以属于同一交互。
- 后端明确结束当前回应后，且该交互存在成功播报，才进入一次原有 8 秒接话窗口。无可播回答、取消或失败时保持关麦，显示实际状态。
- 句段合成或模型生成较慢时可能有停顿，不显示为播放完成，也不无限等待。采用正式协议的超时/连接/长度上限。

不增加自然抢话。AEC 未验收时播报期间不开麦；停止播报与取消 Crabot 业务任务仍是两件事。Manager 调度抢占不属于本次，新输入可能等待旧推理，必须在体验测试中如实记录。

## 3. 实现边界与异常

使用现有 AudioTrack MODE_STREAM 和实际播放游标，支持未知初始总样本数；收帧时持续检查当前连接、turn/playback ID、序号、尾帧及总量上限，最后核对最终样本数。不能把写入 AudioTrack 或接收完音频当作 completed。

回执用真实游标报告已播放样本数。无法确认的状态保持失败/未知；不从文字长度猜测已听到的字数。短尾帧后还有音频、样本数不符、乱序、超时、路由变化、失去音频焦点或服务端取消均不能返回 completed。

按钮停止立即清空队列并停止输出；退出前台、锁屏、来电、断连和新轮继续沿用原有释放规则。迟到消息按当前 ID/连接状态丢弃，不能恢复旧播放或触发接话窗口。默认保留现有一秒音频队列上限，不积压整段音频。

## 4. 升级与数据

两端协调升级至 voice wire v4。版本不兼容显示需要升级，不退回其它音频服务或静默修改消息解释。

覆盖安装 APK，保留现有应用数据、配对凭据、TLS pin 和本机登记向量；本次不修改其存储格式，不以重新配对或清数据作为升级步骤。运行时协议版本与磁盘数据版本分别处理。现有真实录音、声纹向量与凭据不进入仓库、测试日志或公开验证记录。

## 5. 验证与验收

| 步骤 | 验证方式 |
|---|---|
| 连续播放 | 多句不同长度的公开/合成 PCM，证明首句先播、同块只启动一个播放器、最后才 completed。 |
| 长度与回执 | 未知初始长度、最后短帧、实际游标小于收到样本量、缺帧/多帧/乱序/错误 end 等不能误报成功。 |
| 交互结束 | 短确认和最终答复之间关麦；仅后端回应结束后开启一次接话窗口；错误/取消/旧 turn 不开启。 |
| 释放与迟到 | 播放中按钮、后台、失联和新轮立即停播，迟到帧不恢复旧播放器；验证采音没有被句间状态误开启。 |
| 安全真机检查 | 指定不录音、不清数据的测试；不在用户手机运行会清应用数据的完整 instrumentation 套件。 |
| 真人体验 | 覆盖安装后由用户物理按钮触发短问答、工具问答及播报中停止，记录实际听到/停止、句间停顿和后续输入等待。 |

模型输出格式与整链延迟由后端配套验收共同记录。不能以播放器单元测试、录放音文件或正常进程代替用户听到回答、AEC、多人身份或 50 轮速度验收。

自审：只有增量播放和交互结束的必要行为变化；正式 wire 不在本仓重复定义；保持默认关麦、按钮打断、真实 completed 与保留用户数据。无待定设计项，书面确认后按更新的正式协议实现。
