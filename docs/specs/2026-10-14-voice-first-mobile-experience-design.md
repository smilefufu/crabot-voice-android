# 手机端以语音为主的日常交互修订

日期：2026-10-14
状态：待用户确认；2026-10-14 按用户补充纳入手机声纹管理及联系人同步。本稿及交互预览不代表产品代码已经修改。

## 1. 问题与目标

用户已完成一次标签回复的真实播报，但当前首屏是按钮和状态文字堆叠，主入口“开始说话”让人误以为每轮都必须按键。已有本地唤醒、有限采音和回答后连续接话没有形成清楚的日常流程。

本次把现有能力组织成适合语音终端的交互：用户在前台开启一次语音待机，此后通过唤醒词开始一轮，回答后直接续聊。常用页面只展示连接、是否收音、当前阶段、最近回答，以及静音/必要的打断操作。配对、重连、服务详情、手动录音和清除移入设置；“声纹与联系人”提供查看、新增录入、改名、重新录制和删除声纹，并展示实际同步结果。

本次不新增后台/锁屏常驻麦克风，不自动开麦，不延长接话窗口，不增加自然抢话/AEC、Agent 调度抢占、私聊、Agent 自动登记或 ASR 文本回传，不修改音频模型和配置引用。好友创建/绑定和权限管理仍在 Admin，手机不修改这些关系。

手机管理涉及两端协议，配套[后端联系人提交与同步设计](https://github.com/smilefufu/crabot-docs/blob/main/superpowers/specs/2026-10-14-voice-terminal-enrollment-contact-sync-design.md)与本稿一起确认。共同字段仍只在正式 protocol-voice 中维护；确认前不修改正式协议或实现产品代码。

## 2. 现有契约与方案选择

共同接口唯一以 [protocol-voice v0.4.0](https://github.com/smilefufu/crabot-docs/blob/main/protocols/protocol-voice.md) 为准，沿用默认关麦、现场开启本地唤醒、1 秒本地 RAM、15 秒有限轮次、800ms 静音结束、回答后 8 秒接话、后台/锁屏/断连释放，以及播放中关麦的规则。

已核实 MainActivity 的主按钮调用 recordButton，而 toggleWake 是次要按钮。VoiceController 已提供 WAKE → RECORDING → PROCESSING/WAITING → PLAYING → FOLLOWUP → WAKE 的链路；无需为了更换主入口另造状态机。

选择“本地唤醒待机 + 有限接话”：满足每轮不用点按钮，并保留明确的收音范围。不选择持续 ASR 上传所有环境声音。打开 App 就自动开麦会改变既有授权与生命周期契约，本次不选。完全静音时无法靠声音唤醒，重新开启待机仍是一次明确操作。

## 3. 主流程

1. 未配对时以“连接 Crabot”为主入口，进入既有扫码/现场核对流程；已配对自动重连，模型准备及连接未就绪时不开麦，失败给出可操作的重连提示。
2. 连接就绪但静音时显示“麦克风已关闭”，主动作“开启语音待机”。首次需要 Android 麦克风权限；拒绝、撤销或退出前台不开始收音。
3. 开启后显示“等你唤醒”及后台下发的实际唤醒词，例如“你好螃蟹”。状态明确说明“本机唤醒检测”；待机音频只在端侧检测，不上传/转写/落盘。用户不必每轮点按钮。
4. 唤醒命中后显示“我在听”，沿用现有有限录音和停顿结束。当前实现会排除唤醒词，界面引导先唤醒、看到状态变化后说内容，不宣称“唤醒词和命令连读”已验收。点击主体区域可作为手动开始的快捷降级；不是日常必需步骤。
5. PROCESSING/WAITING 显示“正在处理”，麦克风状态明确为关闭，不把本地分段、ASR 或排队猜成 Agent 正在执行。保留真实失败信息，技术字段不堆在首屏。
6. PLAYING 显示“正在回答”，展示现有 playback_start 的首句，收到 playback_end 后更新完整回答。该阶段麦克风关闭，提供“打断并说话”，复用现有按钮打断入口，不宣称自然抢话。
7. 每块 completed 后仍关麦等待同一回应。只有 response_end 才显示“可以接着说”，进入原有 8 秒窗口；有效人声直接开始下一轮，不继承旧 speaker。无接话则回到本地唤醒待机；失败或取消不得伪造接话窗口。
8. “静音”在语音待机和交谈中始终可见，一次操作关闭麦克风并停止播报。App 退后台、锁屏、断连、权限/焦点/路由变化按原规则释放；回前台或重连保持静音，需要明确重新开启。语音待机和交谈期间沿用既有前台屏幕常亮。

停止等待/播报只处理语音交互；已接纳的后台任务继续按原规则负责。用户要取消业务任务仍需新的已授权请求。

## 4. 界面与信息边界

采用适合手机的单页布局：简洁品牌/连接状态，中央状态主体，清楚的阶段标题和一句动作提示，最近回答，底部主要控制。设置作为独立页面/面板；不把端口、模型 ID、声纹分数、分段时间和验收说明放在日常页面。

预览提供“语音陪伴”和“回答为主”两种布局，主流程相同。推荐“语音陪伴”，用留白和状态变化突出免按键交谈；“回答为主”适合常看字幕的用户。最终样式采用用户选择；原型按钮只演示状态，不使用真实麦克风或网络。

- 待机必须显示实际配置的唤醒词；不得用固定文案或猜测用户知道它。
- 显示实际连接/收音状态；只开启本地唤醒时不显示“正在录音上传”。
- 现有协议没有把用户 ASR 文本发送给手机，本次不伪造聊天气泡或用户转写。最近回答仅使用手机已经收到的纯文字，不从 speaker 分段字符串猜测对话内容。
- 有匹配结果时可显示当前识别的联系人名称；unknown/uncertain 显示“陌生人/身份未确认”，不预填 FuFu、不造好友身份。技术诊断保留在设置中的可展开详情。
- 手机主动录入及后台下发登记都使用独立的现场登记视图，避免与日常唤醒主动作冲突；三个不同内容的采样完成后，必须等待后台确认，不以本地录音成功声明联系人已同步。
- 交互目标至少 48dp，状态和动作有文字及无障碍标签；动画尊重系统减少动态效果设置，不依赖颜色表达是否收音。适配小屏、系统栏及长错误文字。

## 5. 声纹与联系人管理

设置中“声纹与联系人”显示本渠道已确认的联系人及本机样本状态。零记录显示空状态和“录入声纹”，不预填 FuFu。未完成任务单独显示“录入中/等待确认”，不冒充正式联系人。列表区分“可识别”“需重新录制”“已删除声纹”和“离线·上次同步”；不把模型分数当身份概率。

1. **新增录入**：输入显示名，在线请求后台分配任务及稳定联系人预留 ID；不由手机自选 ID。点击“开始录入”后才开启有限麦克风，按三段、每段 3–5 秒、整任务 60 秒的既有规则采样。原始音频仅用于本地计算，向量加密存于手机；后台只接收元数据和完成回执。
2. **提交与显示**：采样后显示“声纹已保存，正在同步”。后台原子确认联系人与 active 登记，返回最新目录后才显示“已同步到 Crabot”。首次失败/取消/超时不产生正式联系人。按显示名不合并人，名字相同仍由稳定 ID 区分。
3. **改名**：修改渠道联系人显示名，后台提交后更新手机及 Admin 联系人列表；不改已有好友的名字、绑定或权限，不生成新的联系人身份。
4. **重新录制**：选择已有联系人，复用其 platform_user_id，采用新的 registration_id。新样本完成并获后台确认前保留旧有效样本；成功后切换并清除旧向量。失败/取消不让已有联系人失去原声纹，不改变好友绑定和历史上下文。
5. **删除声纹**：明确确认后先由后台撤销，再清本机向量并回执；未全部完成时分别显示“后台已撤销，等待本机清除”等真实状态。保留曾成功登记的联系人、好友绑定和历史；本次没有“删除联系人/好友”按钮。该联系人可重新录制恢复识别。
6. **离线**：可看标明过期的缓存；新增、改名、重录、删除不可发起，显示连接恢复操作。已发送操作丢回执时保留原 request_id，重连查询/补交原完成回执，不重新生成身份、自动开麦或重传录音。

“及时同步”采用后台提交立即推送和心跳核对版本的组合；在线、服务健康时元数据变更目标 2 秒内到达手机及已打开的 Admin 维护页。联系人在后台提交时即对 list_contacts 可见，不等待用户再次说话或手动刷新。后台的改名、登记和撤销也要反向下发手机。断线后先拉取完整目录、清除撤销向量及恢复待确认结果，完成核对才允许下一轮识别；仅更新目录不自动开麦。

新增、重录或删除前明确停止当前语音交互，登记结束保持静音；进入管理页本身不采音、不停止业务任务。后台发起登记仍须手机现场确认。登记权限不依赖群是否可接纳消息，手机的管理权限只作用于当前配对渠道，不等于 Admin 登录。

## 6. 实施边界与复用审查

MainActivity 负责布局和 UI 状态投影；VoiceController 保留采音、播放、网络及生命周期所有权。日常页面增加实际唤醒词、最近回答、接话窗口等投影，不解析 detail 字符串拼装身份或字幕。管理页使用正式的新目录/命令/回执；加密存储增加目录缓存和待确认操作，具体两端兼容与恢复见配套稿。

主入口调用已有 toggleWake；手动快捷入口和“打断并说话”调用已有 recordButton；静音调用 mute。这些入口原语义与本次动作一致。不能把“回前台/重连”复用为开启语音入口，也不能把“停止播报”当作取消 Worker。

有限采样与模型处理沿用现有登记链路，但不能复用“收到后台 enroll 消息”绕过主动管理鉴权，也不能把 putVector 成功当后台联系人提交。Admin 原 human bearer 管理入口不能直接借给终端；两类已验证身份只共用不含授权推断的登记事务层。失败恢复须验证原 request/任务/模型/ID/revision，不能按名字猜测。

正式协议、后台持久化与手机加密格式均需按配套稿修订；既有配对、有效向量、好友绑定和会话标识保留。协议确认更新后才进入实现。

## 7. 验证与验收

| 步骤 | 验证方式 |
|---|---|
| 主入口与权限 | 初次及重连关麦；一次现场开启进入本地唤醒；权限拒绝/撤销、未连接/模型未就绪不采音。 |
| 免按键完整对话 | 用户一次开启后，仅通过唤醒、说话和接话完成至少三轮；无每轮按键要求，真实回答与 completed 分别核实。 |
| 连续接话 | 多块播报之间关麦；仅 response_end 后进入 8 秒窗口，到期回唤醒；静音/失败/取消不误开窗口。 |
| 静音与生命周期 | 各阶段静音及后台/锁屏/断线立即停采音/播放；恢复不自动开麦，不自动补播旧回复。 |
| 设置及登记 | 扫码/重连/手动降级仍可达，设置页不隐式停播或开麦；手机主动录入及后台现场确认均走三段采样，采样失败无正式联系人。 |
| 管理与同步 | 新增、改名、重录、删除覆盖手机→后台和后台→手机；list_contacts 在提交后可读，在线推送 2 秒目标实测；重连查原操作，重复回执不生成重复联系人。 |
| 身份不变量 | 重录/改名不换联系人、好友或 Session；新样本确认前旧样本有效；删除只撤销样本，失败和并发冲突不伪造同步成功。 |
| 布局与数据 | 真机字号、系统栏、小屏和长文案不遮挡操作；不虚构用户转写/好友；升级前后加密文件核验，不运行会清数据的完整仪器套件。 |

先做状态投影/交互定向回归，再编译安装并核对手机界面，最后由用户现场进行本地唤醒及连续对话。误唤醒、远场准确率、AEC、功耗及 50 轮速度仍需各自验收，不能用漂亮界面代替。

自审：日常页面沿用已实现前台语音规则；新增管理由当前配对终端发起、后台持久确认联系人，样本不上传且不授予好友权限。没有自动收集访客声纹、后台监听或离线身份创建。配套稿明确协议、重录切换和恢复边界；两稿仍待用户书面确认。
