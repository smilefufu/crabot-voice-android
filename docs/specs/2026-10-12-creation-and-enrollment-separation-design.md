## 1. 用户行为与边界

首次创建渠道只配置服务、配对手机和群权限，初始没有正式联系人；后台不要求在向导中绑定好友。人员登记从创建后的维护页发起。手机只承担现场有限采样，向量留在本机加密存储；不读取 Speaker ID 实验 App、手机通讯录或全局好友，不自选联系人 ID、不绑定好友。

新任务的名字是待登记标签。手机现场确认并完成原三段采样、成功加密保存后回报；Admin 核对任务/model/revision 并持久提交后才有正式联系人。手机只显示“声纹采样完成，等待后台确认”，不以本地采样成功声明好友绑定或业务权限。取消/失败/超时沿现有停止与撤销规则，不能制造成功身份。

本次不变更模型、采音来源、VAD/声纹阈值、唤醒、音频帧、三段登记预算、后台/锁屏关麦、播放关麦与按钮打断。不新增手机好友管理、私聊、本地麦克风测试模式或 Agent 登记工具。

## 2. 日常界面

连接状态与语音群状态分别展示。group_ready 来自后端现有群检查，手机不依据名字、样本数量、设备主人或声纹识别自行授予权限。

- 创建完成但群未就绪：显示“手机已连接；语音群尚未启用，请在后台登记联系人并绑定已有 Master”，普通“开始说话”和本地唤醒入口不可启动业务采音，停止入口保持可用。
- 后台有待登记任务：现场登记主按钮照常可用，独立于普通群就绪条件；确认前关麦，登记期间清楚展示当前任务和采样进度。
- 群就绪后：保留当前日常主按钮与折叠维护区，未知说话人仍能正常发言，群权限统一。没有有效声纹不是 VAD 检测失败的原因。
- hello 缺少 group_ready：明确提示需更新后台，不默认已就绪；普通开始/唤醒暂不可用，配对和停止状态仍如实显示。

group_ready 不是长期授权缓存。现有两秒 heartbeat 带回最新结果，后台会在 turn_start 和正式接纳时重验。变为 false 时关闭本地待机与未接纳轮次采音并清楚显示原因，不再开启播放后的接话窗口；已接纳任务及正式播放、过期回答规则保持。变为 true 仅恢复操作入口，不自动开麦或重播。

## 3. 协议与升级

终端整数协议仍为 3；后端拟发布正式文档 0.3.1。hello/heartbeat 增加只读群状态，不新增控制消息种类；enroll/enrollment_done 字段和音频帧不变。首次 pending 任务可引用预留 ID；手机原有匹配仍只使用后端 active 登记，不从 pending 标签认人。

内部 storage_version:1、Keystore、同渠道配对凭据和向量保持，不因本次升级要求重新扫码、卸载、清空或重录真实已登记数据。旧历史占位的判定和恢复由后台负责，手机不尝试从样本列表反推好友权限。

服务端先部署、新手机后升级；旧手机即使忽略新增状态，也会在未就绪 turn_start 被服务端明确拒绝。升级失败保留原文件和凭据；网络重连保持关麦。正式协议更新后逐字段检查，不自行扩展 wire。
