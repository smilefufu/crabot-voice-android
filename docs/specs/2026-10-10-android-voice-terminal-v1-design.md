# Android 语音终端第一期设计

日期：2026-10-10
状态：已于 2026-10-10 获用户书面确认；按正式语音协议进入实现

2026-10-11 修订提示：[身份与联系人修订稿](2026-10-11-android-voice-identity-revision-design.md)待书面确认。本文的家庭成员命名、未知/身份不确定整轮拒绝、登记绑定以及自建/云展示是旧决定，不再继续按这些条款实现；其它一期边界保留。当前 APK 仍是旧规则，不代表修订已完成。

本文件从原 Voice Channel 一期整合稿拆出客户端部分，承接原有行为与验收条件。安卓端相关 spec 从本稿起放在本仓库 `docs/specs/`；[后端配套 spec](https://github.com/smilefufu/crabot-docs/blob/main/superpowers/specs/2026-10-10-voice-channel-v1-design.md) 由 `crabot-docs` 维护。两份稿件共同描述第一期，不复制一份完整后端设计到客户端。

## 1. 目标、约束与已确认行为

用原生 Android APK 连接已部署的 Crabot，完成自然的语音输入/输出，识别家庭成员，至少支持场景 B：同一轮音频内多人依次讲话，包括没有明显静音的换人。第一期不购买硬件，分段、声纹提取与比对在手机完成；未来桌宠可实现相同终端协议，其硬件和动作另立范围。

本仓交付客户端、签名 APK、构建说明及真机验收记录。Crabot 后端、Admin 配置和独立 ASR/TTS 服务由配套 spec 负责。现有官方实验 App 不是产品 APK；FuFu 的实验登记不自动迁移或删除。

### 已确认的一期行为

| 项目 | 本提案的明确建议 |
|---|---|
| 手机生命周期 | 首版只在 App 前台工作；切后台、锁屏、来电或失去音频焦点时立即结束采音及播放。锁屏唤醒和 microphone foreground service 不在首版范围。 |
| 启动方式 | 默认麦克风关闭。支持按钮开始一轮；另有用户明确开启的本地唤醒待机，默认唤醒词“你好螃蟹”。保存配置、启动 App 和重连不自动开麦。 |
| 未知身份 | 首版不允许访客发业务指令。出现未知、未绑定、已撤销或有争议的非空发言时，整轮不提交给 Manager，提示重说或登记；界面保留各匿名编号。 |
| 连续对话 | 完成播报后有 8 秒本地接话窗口；每轮仍重新判断说话人，不能把上一个名字直接继承给下一句话。窗口到期恢复本地唤醒待机或关闭麦克风。 |
| 播放中打断 | 按钮打断始终可用；通过本机回声验收后才启用语音打断。回声能力未通过时，播放期间麦克风关闭，界面明确显示“播放中可点按打断”。 |

用户已于 2026-10-10 确认本 spec 与配套后端 spec；以下行为是首版实现边界。

非目标：同时抢话的逐字分离、在线增量身份定稿、后台/锁屏采音、系统助手替换、开机自启、蓝牙路由、应用商店发布、多终端仲裁、跨手机声纹迁移、私人高权限语音、声音复刻，以及桌宠运动/摄像头能力。

## 2. 技术选择与责任边界

采用原生 Kotlin，使用 `AudioRecord`、`AudioTrack` 和 Android 音频生命周期。端侧基线采用 sherpa-onnx 的现成 pyannote segmentation FP32 分段/聚类及 CAM++ 嵌入/登记比对；不自写另一套 ASR 说话人编号匹配算法，不先抽手机/桌宠通用 SDK。

手机只负责有限采音、KWS/VAD/AEC、匿名分段、登记身份匹配、配对连接、音频播放及真实状态回报。Provider 凭据、Friend 绑定、群权限、ASR/TTS 调用、Manager 业务处理均由 Crabot 负责。手机不自报 Friend ID，也不根据声纹相似度授予权限。

端侧先在完整有限轮次结束后定稿，再提交音频及分段。原生 ASR partial、滚动身份标签和诊断展示都不能提前成为业务指令。完整消息组如何准入、持久接纳和去重见后端 spec §4。

## 3. 收音、唤醒与生命周期

第一期存在两种明确的待机状态：

- **麦克风关闭**：释放 `AudioRecord`，不采样、不做 KWS/VAD、不上传；通过按钮开始。
- **本地唤醒待机**：仅用户显式启用后采样，最多保留 1 秒内存环形缓冲，只运行本地 KWS；不连续转写、不上传、不保存环境音。关掉待机即进入麦克风关闭。

界面始终显示实际收音状态、本地/云音频去向、连接状态和停止按钮。登录、配对、联网和麦克风权限均不是开麦动作。用户开启前台待机或交互时，App 使用前台窗口的保持屏幕亮能力，退出/静音后释放；不依赖 ADB 的保持唤醒设置，也不阻止用户主动锁屏。

按钮或 KWS 命中后建立一轮有限输入。保留最多 300ms 本地前导音频，第一轮排除唤醒词；3 秒内无人声则退出。VAD 用于语音存在和结束判定，不判断“是否在对助手说”，也不能用于发现无静音换人。初始自动结束采用最后一个语音帧后 800ms 静音；一轮上限 15 秒，按钮可提前结束。超限结束时提示“这一段已结束”，不静默丢弃尾部。所有值是待验收的首版提案，不是实测出的默认最优值。

轮次结束后立即停止该轮采样，执行端侧分段/匹配并提交。等待回答时不开麦；用户可点按取消本轮的等待/播报并重新说。此操作只收口语音交互，不等同取消已经开始的 Worker。播报结束后的 8 秒接话窗口只在前台保留，仍做本地 VAD 和当前轮身份判断；超时退出，不延伸成无限监听。

按键打断立即清空播放缓冲，并发送取消当前 `playback_id`。首版语音打断以经 AEC 处理后的 KWS 命中为触发，VAD 只辅助检测，不把任意背景人声当成指令；需要通过本机回声验收，新轮次仍验证身份。AEC 不可用或回声验收失败时使用上表的明确交互降级，不把机器人自己的播报提交为人类输入。首版仅内置麦克风/扬声器；切换蓝牙等音频路由结束交互并显示原因。

切后台、锁屏、麦克风权限撤销、来电、音频焦点丢失、断连、完全静音或退出 App 均释放采音/播放，清除内存音频并关闭交互；恢复前台或重连仍保持关闭，等待用户重新开始。终端模型准备失败时按钮录音也不能绕过身份要求直接执行。

## 4. 连续换人与声纹归属

端侧采用 sherpa-onnx 的现成 pyannote segmentation FP32 离线分段/聚类与 CAM++ 嵌入/匹配。当前 INT8 分段实验出现跨人误归，不能以较快为理由替换基线。现有 FP32 公开拼接也出现相邻簇重叠，按本文保守门控会拒识；真人正常轮次的可用率未证明，属于首个真机验收风险，不能承诺只做接口拼装就完成场景 B。APK/模型版本、文件 hash 和登记向量模型标识一起冻结；授权分发许可在实际打包前逐项核实。

同一轮以音频样本位置确定时间，匿名标签只在该轮有效。每个匿名簇汇总其可用单人语音作登记比对；一个簇中的多段语音共享匹配结果，但不能只取整轮最佳名字。A→B→A 保持三段及顺序；不同未登记者即使均为 `unknown`，也不能合成一个匿名人。

诊断分数不是通用概率。阈值及候选间差值采用所冻结模型的匹配配置，在独立登记/测试集上校准并记录；校准结果未通过不得将自动识别标记为可用。时长不足、相似候选、混音、相邻匿名簇重叠或同一音频争议区间均保留 `uncertain`。VAD 不能检测所有抢话，不能宣称未报重叠就一定只有一人。

手机输出按音频样本定位的有序片段、轮内匿名编号、登记 ID 或 `unknown/uncertain`，不输出伪造的逐字文本归属。报告字段和时间范围要求见后端 spec §3，确认后以 `crabot-docs/protocols/protocol-voice.md` 为正式契约。ASR 由后端按这同一套区间切片转写，不能另猜哪个名字说了哪些词。

重叠或身份不确定时整轮停止业务提交，手机保留诊断并提示重说。身份为 unknown 的有效片段保留各自匿名编号，交由 Admin 的整组准入规则处理；手机不能删除该人后只提交已知成员的话。短接话不能按上一轮身份强行补名字；证据不足时显示原因并提示多说几个字，不截去“停/别开”等争议内容后执行其余部分。

登记阈值与候选差值随冻结的模型配置校准并保存验收记录。公开拼接实验不是客厅可用率证明；若正常换人验收不达标，报告该组合未通过，重新讨论技术取舍，不静默换成 INT8 或增加自写算法。

## 5. 配对、登记与跨端通信

配对、WSS/PCM 格式、控制心跳、发送队列和轮次预算统一遵守后端 spec §5；这些是共同接口提案，确认后只在正式 `protocol-voice.md` 定义字段与状态，不在两个仓库分别发明 wire schema。手机扫描 Admin 一次性二维码，与 Admin 展示同一核对码；Admin 确认后才保存终端专用凭据，登录和配对不自动开麦。

凭据使用 Android Keystore 保护，只连接已配对 voice 实例。TLS 指纹变化须重新配对；不自动信任新证书或回退明文。手机不保存 human/Admin bearer、core Agent/runtime credential 或 Provider key；更换终端和撤销遵循后端的单终端规则。

声纹登记由 Admin 选择 Friend 并创建任务，手机现场点按确认后有限录音。采样数量、时长和 revision 规则以配套 spec §5 为准。向量仅由手机提取并加密保存，不把原录音/向量发送给 Manager；后端只接收登记 ID、显示名、模型标识、版本和状态。等待 Admin 绑定期间显示“登记完成，等待绑定”，不当作已知成员使用。

手机收到撤销时清除相应向量并回报；重连先处理撤销/revision，再开始识别。后端已撤销而手机尚未清除时准确显示状态。模型不兼容、Keystore 丢失、卸载或换手机均需重新配对/登记，不自动迁移实验向量。

一轮提交结果未知时显示“已提交，接纳状态待确认”；查询同一 `turn_id`，不换 ID 重传。断连后不发送缓存的半段音频，不恢复开麦或旧播放。取消等待/播放不会删除已经进入后端持久路径的业务责任。

## 6. 播放、打断与状态展示

只播放后端为当前交互发送的正式回答音频，按 `playback_id`、`connection_epoch` 校验；旧交互、迟到块和重连前的音频丢弃。预算及回答机会以后端 spec §7 为准，首版不承担 TTS 或业务摘要生成。

播放状态为 `started/completed/interrupted/failed`。收到音频、写入 `AudioTrack` 缓冲或排队均不能报 `completed`；实际完整输出才报告完成。退出、断连、丢失音频焦点和打断清空缓冲并报告对应状态，不重播已取消内容。

按钮立即停止当前播报；通过真实 AEC/KWS 验收后才开放语音打断。停止播报与取消 Crabot 任务分别展示，手机不直接 kill Worker。后台任务过了回答机会仍由 Crabot 承担；用户下一次唤醒可询问进度。

界面显示连接状态、实际麦克风状态、本地/云音频去向、录音停止/播报打断动作、识别出的片段/名字及拒识原因。识别诊断与“已接纳/已回复/播放完成”分别显示，不把模型算出名字当成后端准入成功，也不展示业务内部 thought/trace。

## 7. 配置、存储与交付

Provider 和模型选择放在 Admin 的 voice 实例页面；App 展示实际音频去向及状态，不增加第二份 Provider 配置。服务去向改变后先结束当前交互，现场用户重新开始；云端留存按服务规则说明，不用“手机不落盘”代表云服务不留存。

持久保存配对凭据、加密登记向量和必要的模型/登记版本。唤醒环境音、有限录音和收到的播放音频默认只在有界内存，结束、失败、取消或退出后清理，不写普通日志。调试导出必须现场单独开启、有限时长、指定文件并可清除；默认关闭。

APK 只分发已核实授权的端侧组件，不包含 ASR/TTS 权重。构建交付记录固定源码、依赖版本、模型文件 hash 和分发许可；未经核实许可的候选不能进入发布 APK。不提交用户录音、向量、credential、签名私钥或本机绝对路径配置。

APK 与 Voice Channel 记录经过联调的配套版本。连接时核验协议/模型能力，不可识别版本显式拒绝；未来桌宠实现同一正式协议，不以共用 Android 代码为前提。具体构建步骤在 spec 确认后的实施计划中冻结。

## 8. 当前证据与风险

OnePlus 7 Pro / Android 10 / ARM64 已运行官方 CAM++ 登记匹配及 pyannote 文件分段。约 12.5 秒公开混合音频的 FP32 分段加匹配单次约 1.4 秒，边界重叠与 INT8 错归仍存在；这些既不是端到端响应时间，也不是 P95 或真人准确率。证据见[手机文件实验](https://github.com/smilefufu/crabot-docs/blob/main/superpowers/research/voice-scenario-b-poc/README.md)与[中文 ASR 对照](https://github.com/smilefufu/crabot-docs/blob/main/superpowers/research/voice-scenario-b-poc/CHINESE-ASR.md)。

独立 ASR/TTS 回环接口已验证，见[服务实验](https://github.com/smilefufu/crabot-docs/blob/main/superpowers/research/voice-scenario-b-poc/SERVICE-APIS.md)；当前产品 APK、真实客厅换人、录放音生命周期、AEC、唤醒误触发及功耗未验收。手机文件工具和 CPU/GPU 服务耗时均不能代替完整问答体验。

## 9. 验证步骤与验收标准

| 步骤 | 验证方式与通过条件 |
|---|---|
| 手机有限录放音 | 真机按钮 10 轮，停止/退前台/锁屏/断连均释放麦克风；自然停顿及“对/停/别开/不要开灯”不丢掉有效语音，不按旧名字补身份。截图、AudioRecord 生命周期和有限网络证据分别核实。 |
| 场景 B 真人归属 | 两人独立登记与新测试内容；A→B、A→B→A、短接话、同人停顿/变音量，各至少 10 轮，先近讲后客厅位置。记录人工文本/换人区间；无把 B 内容明确标成 A 的业务准入，争议拒识可解释；正常非重叠轮次至少 90% 能完整准入。公开拼接不是验收替代品。 |
| 未登记与撤销 | 先只登记 FuFu、另一人保持 unknown，再登记另一人测试；至少 20 个未知样本和登记后独立新样本。验收集中无未知归已知的准入；删除离线/重连、App 重启与模型版本不匹配状态准确。无需第三人在场。 |
| 隐私与误触发 | 完全静音不采样/上传；本地唤醒待机不上传/转写/落音频。电视、音乐、助手自播各 1 小时，误唤醒目标 ≤1 次/小时且无背景业务执行；失败则不启用自动唤醒验收状态。 |
| 回声/打断 | 按钮触发或 KWS 确认打断到真实静音 ≤300ms；另报开始说唤醒词到 KWS 命中的耗时，不能把两者混同。单独记录 AEC 可用与真实效果；语音打断通过时延及自播不入站后才开启。未通过时界面和行为符合明确降级，不能报告完整语音打断已通过。 |
| 功耗与交付 | 真机分别记录前台唤醒待机与对话 30 分钟的电量、PSS、温度和清理后状态，不以单次采样推断耗电。交付签名 APK、模块包、构建/外部服务说明和上述验收证据。 |

跨端验收还须覆盖同轮全部片段准入、撤销、协议版本不兼容、断连/迟到音频和真实播放回执；沿用后端 spec §9 的整链路延迟、恢复及 system mode 验收标准，不在手机侧另设较宽指标。真人条件暂缺时保留未验收状态，按既有[现场测试步骤](https://github.com/smilefufu/crabot-docs/blob/main/superpowers/research/voice-scenario-b-poc/README.md)准备，不以单人演示宣称场景 B 完成。

## 10. 设计确认与下一步

本稿已自审：客户端/后端边界、有限采音、匿名分段与真实身份、未知整轮拒绝、短词、播放回执、撤销及恢复均有可验证条件；没有新增后端权限入口或独立协议副本。前台限制、未知身份整轮拒绝、8 秒接话窗口、回声未通过时按钮打断均已获用户确认。

用户已确认本稿与配套后端 spec；先在 `crabot-docs` 更新正式协议，再分别编写“步骤 → 验证方式”的实施计划。安卓端后续 spec 与计划留在本仓库；偏离确认范围须先报告并重新确认。
