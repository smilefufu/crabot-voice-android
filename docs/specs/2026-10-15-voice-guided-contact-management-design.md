# 语音引导声纹与联系人管理

日期：2026-10-15
状态：2026-10-15 用户认可全语音管理业务方案；主控工具按后端配套稿接入现有功能族加载。未修改手机代码、模型、阈值或用户数据，前置设计按各自确认状态推进。

配套[后端全语音登记设计](https://github.com/smilefufu/crabot-docs/blob/main/superpowers/specs/2026-10-15-voice-controlled-enrollment-design.md)。前提为[设备所有者激活](2026-10-15-device-owner-activation-design.md)及[请求级授权](https://github.com/smilefufu/crabot-docs/blob/main/superpowers/specs/2026-10-15-group-request-authorization-and-interruption-design.md)；正式跨端协议只引用 [protocol-voice](https://github.com/smilefufu/crabot-docs/blob/main/protocols/protocol-voice.md)。

## 1. 体验与边界

Master 在正常语音轮发起登记 Thea 后，手机自动进入有限的引导登记：播报读句 → 自动采样 → 本地验证 → 下一段 → 等待后台提交 → 播报结果。正常路径不用再打开页面或逐段点击“录这一段”；手机显示对象、三段进度、当前播报/采音及取消按钮。

后台已验证的现场语音请求允许这一次有限采样，不等于一般 remote 开麦权限。来自其他渠道或原 human Admin 下发的普通登记，仍保留现行手机现场确认；手机按钮维护也沿原入口。不能仅因收到一个 enroll 或 terminal credential 就按语音自动模式开麦。

不新增后台/锁屏录音、云声纹服务、麦克风长期监听、声纹身份强认证、私聊模式、自然抢话/AEC 或对原实验 App 的导入。手机不解析 Master 权限、不创建好友，只显示后台已确认的联系人与结果。

## 2. 明确的任务上下文

只有当前前台、已认证并已同步的连接可接受后台验证的语音管理任务。任务明确携带对象、采样模式、服务端截止时间、登记/模型/目录引用及固定提示的播放关联；完整字段由正式协议定义。重放任务、过期 epoch、错模型/对象/版本、终端在后台或现有任务冲突均拒绝，不自动覆盖当前任务。

初始状态是“等待引导播报”，麦克风关闭。每段流程为：核实任务仍有效 → 播放当前提示 → 真实 completed → 有限采样 → 验证/清空原音频 → 下一段或提交。管理提示与普通业务播放分别关联，普通 response_end 或过期的业务播放事件不能开启采样。播放失败、打断或超时立即保持关麦并显示原因。

三段采样及首次完成回执须在原服务端 60 秒登记窗口内有效接纳，不因重试、网络或重新进入页面自动延长；无有效完成先终止采样，再按原 ID 查询/取消任务。期限内已持久接纳的结果、后台已提交成功但 UI 回执晚到，都按后台查询结果收口，不重新录制。

## 3. 本地采样和身份质量

继续使用现有分段与 embedding 模型、16kHz/mono 采样、每段 3–5 秒及现有有效人声下限。维度、有限值和非零范数逐段验证；多说话人、重叠或分段非法拒绝该段。日常短句识别继续由模型可用性与有效匹配决定，不恢复固定秒数门槛。

三段之间增加现成 embedding 比对的一致性检查：每一对样本均达到当前项目匹配分数 0.50 后，才按现有三段合成方式建立候选。复用模型的比对结果并验证返回结构，不手写另一套声纹算法；0.50 是已有项目候选阈值，不是可靠身份保证或行业标准，不新增用户配置项。该检查共享给新所有者激活和录入路径；既有 active 样本不会因升级自动被重新打分撤销。

登记新人时，再用候选与当前后台 active 且本机有效的样本按原 score/margin 规则比对；检测到与既有人物匹配或多个档案相近，停止自动新建并报告身份冲突，请 Master 澄清，不能按名字覆盖。重录时保持指定联系人的稳定身份，并对其他档案冲突做同样检查；与旧样本不匹配本身不能禁止经 Master 明确要求的重录恢复。

三段读句内容不同且足够长，例如“你好，我叫 Thea，很高兴认识你”“我正在录入自己的声音，以后请叫我 Thea”“请记住我的声音，以后我会经常和你聊天”。固定提示避开配置的唤醒词。登记不调用云 ASR 校验朗读文字，也不把自称姓名或 ASR 编号作为真实身份依据。参与者主动跟读表示愿意采样，但模型无法证明现场那个人的真实姓名。

首次激活、原手机页面登记和新语音引导尽量共用采样验证与加密提交层；启动授权、提示播放和结束后的待机恢复分别保留各自场景语义，不能把旧的“后台 enroll → 等按钮”入口改成无条件自动开麦。

## 4. 退出、插话与采音生命周期

采样数据只进入当前任务的本地特征计算，不走业务音频上行、ASR、turn_end 或 Agent inbox。采样中出现名字、指令或“我是 Master”不产生权限。新的业务会话和管理采样不能同时打开同一麦克风。

采样期间保持现有本地唤醒检测作为退出操作：命中配置唤醒词，立即停止采样、撤回候选并按原任务取消这个未完成登记，不将该声音纳入样本、不直接借原 Master 身份执行随后的话。这只是撤回当前样本许可，不控制其他业务；用户再正常唤醒发起新指令。按钮静音/取消始终可用。播放时关麦，不承诺隔着 TTS 也能语音退出；需要立即停止时使用终端控制。

退后台、锁屏、来电、路由/焦点变化、权限撤销、断连和静音都释放麦克风与播放，候选音频立即清空，不自动复活未完成采样。已后台提交的结果仍可在重连后查询；未提交候选按原任务结果清理，不擅自替换旧样本。

语音引导顺利完成后，只有此前用户已开启待机、同一前台连接与本地待机授权一直有效，才在结果提示播完后回到原本地唤醒待机；不打开无限普通录音或伪造业务接话事件。取消/断连/后台/权限变化立即清除恢复条件，重连保持关麦。首次设备激活及普通按钮管理结束仍沿原规则关麦，不借此自动开启待机。

## 5. 保存、同步与显示

三段候选和待完成回执先原子加密保存，再发送完成事实；显示“声纹已保存，正在登记联系人/好友”。后台确认整项管理完成、正式目录应用后才显示成功；本地均值计算或 WS 已发送都不是成功。

好友绑定由后台完成，终端不发送 friend_id、permission 或模板。目录中的新联系人沿既有提交即查询可见、立即推送和 2 秒心跳核对同步；普通好友身份的最终状态来自后台只读结果，不靠本机样本数或显示名推断。

重录失败保留旧 active，成功后切换；改名不换 ID 或全局好友名字；撤销声纹保联系人、好友和历史。已撤销未清设备向量时分别显示真实状态。对“删除联系人/好友”不自作解释，沿后台澄清或不支持结果处理。

结果提示使用与原任务绑定的管理播放，不把样本、工具日志或整段 Agent 输出直接播放。Master 指定私发时，正文交给后台通讯路径；设备不重复播报该正文，仅按允许内容说明投递状态。

## 6. 协议、升级和验收

与设备激活统一拟升级 wire 6，正式字段在后端协议确认后对齐；存储保留旧配对、向量、联系人 ID，并版本化保存有界引导任务的待确认事实，不持久化原音频或可复活的开麦许可。后台先升级、APK 保留数据覆盖安装；升级失败保留密文，不能为了适配新流程清 FuFu 数据。

| 步骤 | 验证方式 |
|---|---|
| 启动与播放守卫 | 非语音管理任务仍须按钮确认；当前现场任务可自动引导；错对象/epoch/过期/普通 response_end/未 completed 均不开麦。 |
| 三段与一致性 | 同人不同读句通过；两人混录/重叠/无声/无效特征/低分/已有档案冲突拒绝；旧样本在失败后保留，日常识别无时长回退。 |
| 生命周期 | 唤醒词退出、按钮取消、锁屏/后台/来电/断连、播放失败及 60 秒到期都停止；旧回调不能重启采样，普通音频不会误上行。 |
| 结果与恢复 | 每阶段写盘/网络失败、提交后崩溃、丢回执、旧 revision、撤权及重连；同操作不重复建身份，状态不冒充成功。 |
| 体验与真机 | 无逐段按钮完成三段；登记成功后的待机只恢复既有授权；真实两人 A/B 发言和未知者分别验证，公开文件与单人自演分开报告。 |

质量阈值的真实家庭误拒/误录、现场 Thea 参与及整体耗时均待验收，不因公开文件测试通过就宣称准确可靠。先用公开音频和隔离状态准备回归，不把真实录音/向量入库；真机测试须保留当前配对和声纹。

前置设计确认后更新正式协议、写实施计划、实现并定向测试/review，安卓按既有授权直接 main。当前仅维护本 spec。

自审：免按钮路径限定已授权现场语音任务，采样是数据而非新命令，自动待机恢复仅继承仍有效的原许可；未新增后台监听或手机好友权限。
