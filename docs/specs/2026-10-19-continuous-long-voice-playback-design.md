# Android 长回答连续播放与响应速度配套修订

日期：2026-10-19。状态：用户已明确确认本配套修订稿、后端设计和一处精确提示词文字，授权先同步正式协议再实施/测试；正式协议已同步v0.9.0 / wire9，产品实现与验收进行中，尚未再次安装APK。配套[后端长回答连续分段播放稿](https://github.com/smilefufu/crabot-docs/blob/main/superpowers/specs/2026-10-19-continuous-long-voice-playback-design.md)，正式wire及共享类型只以[protocol-voice](https://github.com/smilefufu/crabot-docs/blob/main/protocols/protocol-voice.md)为准，本仓不维护第二份协议。

## 1. 用户行为与范围

长回答由后台自动分段，手机按顺序连续播放；不用用户点下一段，也不要求Agent减少字数或自行拆voice_reply。首段到达即可播放，不等整段生成；同一个逻辑回答仍共用一个AudioTrack，句间不关开播放器、不重新识别人、不打开麦克风或接话。

voice_reply继续是后台提取的普通正文；本轮不增加SSML解析、句子/情绪控制标签、TTS直连或模型配置。手机只处理正式wire给出的文字与PCM，后台的自动分段不变成端侧XML转换。

只调整出站播放、文字展示、真实进度/终态回执及必要兼容。唤醒、采音/VAD/ASR、声音登记、所有者、联系人、好友、权限、群/私发目标和模型配置不变。固定管理读句的有限采样流程不因共用AudioTrack而获得无限时长。

## 2. 手机职责

- 不解析模型标签、调用TTS或自行改写回答；接收后台有序的文字片段和连续PCM。文字增量追加，最后核对文字段数；显示文字不等于该文字已播放。首段PCM就绪后即沿原播放方式消费，不等待后续文字或完整回答结束；保留AudioTrack正常启动所需缓冲，不把队列一秒上限当作出声前的凑满门槛。
- 音频帧仍检查当前playback/连接、序号及最后短帧。取消整段480000样本和25秒墙钟限制；累计计数使用Long且必须落在协议安全整数范围，不截断成Int。
- PCM队列仍最多一秒，消费后即清空；后台按播放进度限制发送，不让长回答增加音频队列。最多每500ms报告一次真实游标进度，未前进不能伪装进展，不能以收到/写入量代替。
- 按后端共同阶段语义检测卡住：有未消费PCM但实际游标五秒不动才播放失败；等待有界合成或下段文字不能误判成设备卡住。网络心跳仍沿原断连保护。
- 收到结束标记后，文字/音频完整并且真实游标达到最终总数才持久保存completed；完整收到、一次内部段完成或整个音频已写入均不是完成。
- 同一回应还有其它块时保持关麦。只有后端response_end且满足原成功条件，才开启一次原8秒接话；后台通知不额外开麦。原60秒等待不能中途截断已接纳且仍有真实进展的回答。
- 按钮打断、静音、退后台/锁屏、断连、来电/焦点及路由变化沿原规则立即释放，迟到帧不能复活播放；部分/未知不自动重播。

响应速度按后端稿第8节核对：终端以同一单调时钟量最后有效人声结束到真实播放起点，VAD等待计入，按钮结束采音单独标明；后台回执到达时刻不能替代实际首声。按原turn/playback关联阶段时长，普通日志不保存录音、声纹或回答正文。连续正文播放时另记音频队列耗尽的次数/持续时间，避免把整段completed误当成无额外空档。

## 3. 兼容及数据保护

与后端协调发布Android0.8.0/code17、wire9。有效v3–v8配对可读并以wire9复用原凭据，新码只用wire9，旧客户端明确提示升级。不卸载、不清数据、不要求重扫/重录或更换ADB密钥。

播放回执journal用v2保存Long样本数，兼容读取v1；原文件校验及逐文件备份后原子迁移，失败保旧且不假称成功。至多128条回执，原有重交/确认清理语义保留，不复制整个应用目录。旧completed沿原样提交，旧interrupted/failed不改写成成功；后台unknown也不因本次升级恢复播放。

SecureStore配对/声音密文、Keystore、人物引用不为本修订改变。原始音频和向量不进仓库或普通日志；验收只记录必要版本、时长、队列峰值、游标及终态。

## 4. 步骤与验证

| 步骤 | 验证方式 |
|---|---|
| 正式协议先行 | 用户确认后更新共同协议，再逐字段对齐手机；不先行写另一套消息定义。 |
| 播放进度及有界队列 | 合成超过20/30/60秒与三分钟PCM，持续推进不被墙钟截断；首段不等全文或预缓冲满才消费；队列峰值不随总长度增长，数字溢出/错误游标/重复帧/尾帧均拒绝。 |
| 文字、完成和生命周期 | 逐段文字无丢失/重复，结束段数核对，真实完成/中断/回执恢复；句间不开麦，原通知与8秒接话保持。 |
| 故障及兼容 | 假心跳/不动游标、等待合成、断连和实际播放卡住分开验证；v1回执迁移及失败保旧，原配对及样本不变。 |
| 真机 | 只运行不清数据的指定测试；与后端同组升级，按共同目标记录50轮预热无工具问答首声median≤3秒/P95≤5秒，并验证工具前一次接单、长于一分钟完整回答、额外空档和中途停止。单次2–3秒反馈、后端日志或虚拟时钟不代替整链真实播放验收；未完成项明确保留。 |

确认后在本仓编写实施计划，定向测试、本次diff审查及构建通过后按仓规提交main；真实模型、真机播放和多人识别分别报告。已有Master两条历史绑定的所有者恢复另行核查，不借本修订更改身份。

自审：只有连续长回答及响应速度核对所必需的播放/回执变更，无SSML、情绪映射、新任务、模型设置或用户操作，无新的回答总秒数/字数限制。
