# Android 语音终端身份与联系人修订

日期：2026-10-11
状态：待用户书面确认；产品代码及已交付 APK 尚未按本稿修改

本稿修订 [Android Voice v1 设计](2026-10-10-android-voice-terminal-v1-design.md)中未知身份、登记对象及服务展示的旧规则。[后端修订](https://github.com/smilefufu/crabot-docs/blob/main/superpowers/specs/2026-10-11-voice-channel-contacts-and-group-revision-design.md)负责联系人/Friend、唯一群和授权消息组；正式字段仅由 `crabot-docs/protocols/protocol-voice.md` 维护。本仓不复制一份 wire schema。

## 1. 目标与范围

一期仍是前台手机语音终端、默认关麦、按钮或显式本地唤醒、有限输入、端侧分段/声纹、外部 ASR/TTS、正式回答播放。每个 Voice Channel 只有一个普通群，合法陌生人可以在该群发言；手机不自行设访客准入或删除陌生片段。

本次不新增私聊按钮、不实现 Agent 登记工具、不换模型、不增加在线定稿、声纹云服务、同时抢话逐字分离或后台录音。原 8 秒接话、AEC 未通过时播放关麦/按钮打断、生命周期收口及模型 hash 保持。

## 2. 匿名分段与身份结果

分段时间线先决定音频内容的匿名说话人归属，声纹再决定匿名簇能否对应一个登记记录。两者失败的处理必须分开：

| 状况 | 手机行为 |
|---|---|
| 非重叠且完整的片段，声纹 matched | 报当前有效 registration ID，由后端解析渠道联系人及 Friend。 |
| 非重叠且完整的片段，声纹 unknown | 保留轮内匿名编号和原音频，正常提交整轮。 |
| 非重叠且完整的片段，时长不足/候选差值不足等 identity uncertain | 保留 uncertain，不携带猜测的登记 ID，正常提交整轮；后端按陌生人处理。 |
| 匿名分段重叠/无效，无法确定内容归属 | 终止本轮，保留诊断并提示重说，不提交已知人的部分内容。 |

当前 `Identity.report` 把短簇/候选不确定和重叠都编码为 uncertain，`completeCommand` 因此拒绝所有 uncertain；修订后内容完整性单独检查。保留严格的区间/重叠检查，不用截短争议区间伪造完整内容，也不另发明一套说话人算法。

每个匿名簇可以通过同轮多个单人片段汇总声纹证据；A→B→A 保留三段顺序。短接话不继承上一人的名字。unknown/uncertain 和无登记候选均可正常作为匿名发言。

轮内同一匿名人使用同一编号，不同未知者不合并；下一轮编号重新开始，不承诺陌生人跨轮跟踪。提取不到可用声纹向量时可保留 uncertain；分段/聚类失败时不得伪造有效匿名时间线。整体模型初始化失败沿原生命周期规则不开放录音。模型分数留在诊断，不作为身份概率或权限依据。默认不保存未登记者的向量。

## 3. 登记对象与界面

登记任务属于一个稳定渠道联系人，登记 ID 只标识这次样本。Admin 创建联系人、解析 Friend 绑定并下发任务；手机不创建 Friend、不修改绑定、不持有 Admin/Provider 凭据。

手机仍按 registration ID 加密存储向量并核对模型/revision。重新登记换新的 registration ID，联系人身份保持；撤销先由后端失效，终端清除向量并回报。未绑定 Friend 的联系人可以有有效声纹；这仅说明模型认出哪个联系人，后端仍将其作为陌生人，不再把登记完成显示成“等待授权才能说话”。

界面逐段显示时间范围、匿名编号、识别到的联系人或“陌生人 / 身份未确认”，并区分“声纹样本完成”和“本轮已接纳”。显示名只作展示，Friend 判断由后端完成；不能依据手机上的名字声称已授予权限。没有声纹登记也能测试群聊，不要求先录入 FuFu 才允许录音。

模块/页面名称使用“语音渠道”“渠道联系人”“声纹登记”，不限定家庭或客厅。Admin 负责联系人/Friend 配置；手机只提供现场有限采样，不复制一个成员权限页面。

## 4. 服务展示、通信与兼容

ASR/TTS 仍由 Crabot 通过外部 API 调用，手机仅展示实际 ASR/TTS 服务地址及连接状态，不显示配置者自选的云/自建分类，也不猜测 endpoint 所属环境。实际麦克风状态、本地唤醒状态、停止/打断入口继续可见。

后端修订增加登记所属联系人、删除 hello destinations 的 kind，因此共同协议整数升级到 2。手机与后端同批更新，v1/v2 不混连；不能通过容忍缺字段继续使用旧身份规则。端侧模型与 PCM 格式不变，协议版本失败不开放录音。服务连接变更仍结束当前交互，现场重新开始。

没有产品历史登记迁移；原官方实验 App 和 FuFu 实验向量保留。旧产品 WIP 的配对/登记不自动转为新联系人；联调使用独立测试数据，确认不兼容时给出重新配对/登记提示，不自动清空旧 App 数据。交付时记录新 APK/hash、源码、协议及配套 Channel 版本，旧 APK 的测试成绩不等于新规则验收。

## 5. 后续私聊与 Agent 登记

未来按钮开启私聊后，由当前每段声纹确定联系人及其 Friend 私聊，而不是锁定首次说话人。A→B→A 分别路由对应 Session，返回 A 时继续 A 的上下文；陌生人/身份不确定者普通私聊忽略。当前一期仍只有 group，不增加 private 状态、按钮或 wire 字段。

未来 Agent 可发起有限现场登记并完成联系人/Friend 创建或绑定，手机复用有限采样和现场确认；不持续采集所有访客声纹。具体 Agent 工具与 private 的跨会话输入/播放在相应后续 spec 定义。

## 6. 验证步骤与验收

| 步骤 | 验证方式和通过条件 |
|---|---|
| 正式协议与解析 | 确认后按共同协议改控制消息/登记 metadata；v1/v2 握手明确拒绝；运行原有限 PCM、配对/TLS/Keystore 回归。 |
| 身份与内容门控 | 零登记、unknown、短簇 uncertain、候选相近 uncertain 保留全部有效片段并正常提交；重叠/非法区间/分段运行失败无部分业务提交，不通过删除内容逃避错误。 |
| 联系人与登记 | 重登换样本 ID、不换联系人 ID；撤销/重连先清除；登记完成不自动等于 Friend 绑定；手机不发 Friend ID。 |
| 群整链路 | A→unknown→B→A 全部进入同一群，Agent 实际输入身份与文本逐段对应，一次唤醒；仅登记 FuFu 时未知者仍能说话，不被赋予 FuFu。 |
| 生命周期与输出 | 原前台、锁屏/后台/权限/焦点收口、默认关麦、本地唤醒无上传、真实播放 completed、打断不重播保持。 |
| 真人与交付 | 原独立登记/测试集、正常场景 B 至少 90% 可用、未知不误归已知、KWS/AEC、功耗及整链延迟继续真机验收；合成/公开文件和模拟器仅作为补充。 |

自审：手机知道声纹结果但不授予 Friend 权限；身份 unknown/uncertain 与内容无法归属已分开；不引入陌生人跨轮追踪或后台采样。模型故障不假造匿名结果，内容失败不丢片段后执行。真实条件不足仍标待验收。

本稿与后端修订确认后，先更新正式协议，再修订本仓实施计划并实现。当前 APK/旧预览尚未具备新规则，不作为修订验收证据。
